排查后发现：

- 编号 `40` 的胶水没有退掉
- 编号 `234` 的胶水退了两遍

```java
// 查看胶水退仓库源代码 glueReturnWarehouse
@Override
public void glueReturnWarehouse(List<Glue> glueList, String returnReason, String remarks, String returnDate,
        String glueReturnOrderId, String returnGrade) throws MyCimException {
    try {
        JSONArray glueJsonArray = new JSONArray();
        TransactionLog transactionLog = baseService.startTransactionLog(
                ThreadLocalContext.getUsername(), GlueHistory.TRANS_RETURN_WAREHOUSE);
        for (Glue glue : glueList) {
            glue.setReturnGrade(returnGrade);
            JSONObject materialLotJson = getMaterialLotJsonByGlue(glue);
            glueJsonArray.add(materialLotJson);
            glue.setStatus(Glue.STATUS_RETURN_WAREHOUSE);
            glueRepository.merge(glue); // 1. 修改胶水状态

            GlueHistory glueHistory = new GlueHistory(
                    glue, GlueHistory.TRANS_RETURN_WAREHOUSE, ThreadLocalContext.getUsername());
            glueHistory.setObjectRrn(getTransactionRRN());
            glueHisRepository.save(glueHistory); // 2. 添加胶水历史表

            // 退仓库后将原材料信息保存至物料信息表，供补打标签使用
            MaterialReturnInfo materialReturn = new MaterialReturnInfo();
            materialReturn.setObjectRrn(getObjectRRN());
            materialReturn.setMaterialLotId(glue.getName());
            materialReturn.setMaterialName(glue.getGlueType());
            materialReturn.setReceiveQty(1.0);
            materialReturn.setMaterialType(MaterialReturnInfo.MATERIAL_TYPE_GLUE);
            materialReturn.setReason(returnReason);
            materialReturn.setRemarks(remarks);
            materialReturn.setReturnWarehouseTime(returnDate);
            materialReturn.setMaterialReturnOrderId(glueReturnOrderId);
            materialReturn.setReturnGrade(returnGrade);
            mateialReturnRepository.save(materialReturn); // 3. 添加退料信息
        }
        baseService.markTransactionLog(transactionLog);
        // 发送数据到 WMS
        gcService.sendRequestToWmsUpdateMLot(
                glueJsonArray,
                GlueHistory.TRANS_RETURN_WAREHOUSE,
                WmsMmsMaterialLot.ACTION_TYPE_GLUE_RETURN_WAREHOUSE);
    } catch (Exception e) {
        throw ExceptionHandler.handlerException(e, log);
    }
}
```

以上数据中，编号 `234` 的重复记录已删除；和 WMS 比对后没有再发现异常，当前可以先按已恢复处理。

## 5. 晶圆处理异常

![image.png](https://obsidian-oss-sync.oss-cn-hangzhou.aliyuncs.com/pictures/20241021163704.png)

现象：处理按钮消失。

一开始以为操作记录存放在 `backend_wafer_receive_his` 表中，但删除该表记录后现象没有变化。调试后发现，真正决定处理进度的是 `PROCESS_RELATION` 表，`backend_wafer_receive_his` 更像是顺带留痕。

结论：删除 `PROCESS_RELATION` 中对应记录后，界面可恢复处理。

```sql
-- from_rrn 是 waferReceive 的 objectRrn
SELECT * FROM PROCESS_RELATION WHERE from_rrn = '347143161';
```

## 7. 工单结单后在线数量为 0，但工单明细表还有数量

这类问题的关键是区分“报表筛选逻辑”和“工单本身状态”。

1. 在线明细报表数量为 `0`，通常是因为该报表只统计 `WAITING`、`RUNNING`、`HOLD` 等状态的批次；本次包装批次状态为 `COM`，没有被筛选出来。

   ![image.png](https://obsidian-oss-sync.oss-cn-hangzhou.aliyuncs.com/pictures/20241021163755.png)

2. 工单明细表里的数量，本质上仍然来自工单数据表，说明该工单下还有未清理的数据。
   需要注意：工单状态是 `AUTOCLOSE` 时，只表示这个工单下的批次已经全部投批，不代表在线数、报废数、完成数、计划数全部归零。

   ![image.png](https://obsidian-oss-sync.oss-cn-hangzhou.aliyuncs.com/pictures/20241021163809.png)

3. 处理时建议把工单下所有真空包批次都列出来，找到数量不为 `0` 的批次，再看其批次状态。通常这类批次状态比较特殊，往往是产线漏处理，误以为已经结束。

```sql
SELECT l.QTY1, l.LOT_STATUS, l.INPUT_QTY1, l.*
FROM LOT l
WHERE LOT_RRN IN (
    SELECT LOT_RRN
    FROM LOT_EXT le
    WHERE OUTER_ORDER_NO = 'ZJZC230707004'
);

SELECT mpl.PACKED_STATUS, mpl.*
FROM MM_PACKED_LOT mpl
WHERE WORKORDER_ID = 'ZJZC230701003'
  AND "TYPE" = 'VBOX';
```

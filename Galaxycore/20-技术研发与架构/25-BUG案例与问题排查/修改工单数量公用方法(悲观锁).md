
在处理工单数量更新的过程中，为了确保数据一致性和防止并发事务导致数据覆盖，采用了悲观锁来对工单表进行操作。以下是对实现代码的详细整理与分析。

## **1. `PrpSetupServiceImpl.java` - 公共方法实现**
### **功能：**
`forUpdateWorkOrderQty` 方法用于更新工单的数量，根据不同的操作类型 (`TRANS_INWMS` 或 `MOVEOUT_KEY`)，更新工单的数量信息，并且在事务中进行处理。该方法在更新时使用了悲观锁来确保在操作过程中数据的唯一性。
### **代码分析：**
```java
@Override
@Transactional
public void forUpdateWorkOrderQty(String workOrderId, Integer quantity, String transId, String action, long transRrn, String name) {
    try {
        // 获取工单并锁定，防止其他事务并发更新
        WorkOrder workOrder = getWorkOrderByIdForUpdate(workOrderId);
        
        // 根据不同的操作类型更新工单数量
        if (StringUtils.equals(action, Lot.TRANS_INWMS)) {
            // 入库操作，更新工单的在制数量和完成数量
            workOrder.setWipQty(workOrder.getWipQty() - quantity);
            workOrder.setCompleteQty(workOrder.getCompleteQty() + quantity);
            workOrder.setLastUpdateUserId(name);
            String namedSpace = baseService.getNamedSpace(ThreadLocalContext.getFacilityRrn(), ObjectList.WORKORDER);
            workOrder.setNamedSpace(namedSpace);
            workOrder.setInstanceId(workOrder.getWorkorderId());
            workOrder.setObject(ObjectList.WORKORDER);
            workOrder.setOwner(workOrder.getLastUpdateUserId());
            
            // 更新工单命名空间和相关信息
            baseService.updateNamedObject(workOrder, transRrn);
        } else if (StringUtils.equals(action, TransactionNames.MOVEOUT_KEY)) {
            // 出库操作，更新工单的报废数量和在制数量
            workOrder.setOwner(name);
            workOrder.setScrapQty(workOrder.getScrapQty() + quantity);
            workOrder.setWipQty(workOrder.getWipQty() - quantity);
        }

        // 更新工单数据
        workOrderRepository.update(workOrder);
        insertWorkOrderHistory(transRrn, transId, workOrder); // 插入工单历史记录
    } catch (Exception e) {
        throw ExceptionHandler.handlerException(e, logger); // 异常处理
    }
}

private WorkOrder getWorkOrderByIdForUpdate(String workOrderId) {
    try {
        return workOrderRepository.getWorkOrderByIdForUpdate(workOrderId); // 获取并锁定工单
    } catch (Exception e) {
        throw ExceptionHandler.handlerException(e, logger);
    }
}
```
### **功能说明：**
- **悲观锁机制：** 使用 `getWorkOrderByIdForUpdate` 方法通过 SQL `FOR UPDATE` 语句来确保工单数据的悲观锁，从而避免并发操作对数据的覆盖。
- **操作类型：**
    - `TRANS_INWMS`：入库操作，更新工单的在制数量和完成数量。
    - `MOVEOUT_KEY`：出库操作，更新工单的报废数量和在制数量。
- **事务处理：** 方法通过 `@Transactional` 注解确保该方法在事务中执行，保证操作的原子性。
- **工单历史记录：** 每次更新工单数据后，会插入工单历史记录，确保操作的可追溯性。

## **4. `WorkOrderRepositoryImpl.java` - 获取并锁定工单**
### **功能：**
`getWorkOrderByIdForUpdate` 方法通过 SQL 查询并使用悲观锁，确保工单数据的唯一性。
### **代码分析：**
```java
@Override
public WorkOrder getWorkOrderByIdForUpdate(String workOrderId) throws MyCimException {
    try {
        // 通过工单ID进行查询，并加上悲观锁
        WorkOrder workorder = getSqlBuilder().select(columnNames)
            .from(tableName)
            .where("WORKORDER_ID = '" + workOrderId + "' FOR UPDATE ")
            .queryOne(WorkOrder.class, false);
        return setWorkOrderInfo(workorder);  // 返回工单信息
    } catch (Exception e) {
        throw ExceptionHandler.handlerException(e, log);  // 异常处理
    }
}
```
### **功能说明：**
- **悲观锁：** 通过 SQL 中的 `FOR UPDATE` 子句，对工单数据加锁，确保在事务期间其他操作不能修改该工单数据。
- **查询工单：** 使用工单ID查询对应的工单信息，并返回。

---
## **总结：**
- **悲观锁机制：** 通过在查询工单时使用 SQL 的 `FOR UPDATE`，确保在事务中操作工单数据时不会被其他事务修改，防止数据覆盖问题。
- **公用方法：** `forUpdateWorkOrderQty` 方法统一处理工单数量更新，支持不同操作（如入库、出库）场景，并且在事务中执行，确保数据一致性。
- **历史记录：** 每次工单数量更新后，都会插入历史记录，确保操作的可追溯性。
- **调用流程：** 各个服务层（`LotServiceImpl` 和 `PackageServiceImpl`）通过调用 `prpSetupService.forUpdateWorkOrderQty` 方法来更新工单数量，并确保通过事务和锁机制保证操作的正确性。

# FT RT FA过站与缺陷率统计优化需求

## 一、需求概述

基于近期 ATE 大数据与 FT 数码型号三遍测试差值分析，计划优化 FT ATE 评估导入 FT RT FA 指定 code 的回收逻辑。

目标是将三遍测试差值较小的 code 直接产出，不再进入回收流程，从而减少 RT FA 的投入测试量，并同步修正 MES 中与 FT RT FA 相关的过站、HOLD 缺陷率统计及报表统计逻辑。

本次需求包含以下 3 个部分：

1. FT RT FA 过站逻辑调整；
2. MES HOLD 缺陷率抓取逻辑调整；
3. FT RAW DATE 报表统计逻辑调整。

## 二、需求背景

现有业务中，MES 在 FT RT 站点不允许产生 F 等级，目的是防止员工将少料、压碎等异常数量误输入到等级数量中。

但随着 FT ATE 测试优化推进，部分物料在 FT RT 站点需要允许直接产出 F，以减少后续 RT FA 的测试投入。

与此同时，当前 HOLD 缺陷率统计和 FT RAW DATE 报表统计仍主要依据 FA 站点 F 数量进行计算，已经不能准确反映 FT、RT、FA 三站合并后的真实缺陷情况，因此需要同步调整统计口径。

## 三、需求明细

### 3.1 需求一：MES FT RT FA 过站逻辑调整

#### 现有逻辑

- MES 在 FT RT 站点不允许产生 F；
- 产线员工手工录入 key 数量；
- 当前不校验过站文件数量与人工 key 的 F 数量是否一致。

#### 目标逻辑

- 允许 FT RT 站点产生 F 等级；
- 人员 key 的 F 数量必须与过站文件中的 F 数量保持一致；
- 若存在少料、压碎等芯片，相关数量需 key 入 RT 数量中，避免误录入 F 数量。

#### 变更目的

- 适配 FT ATE 测试优化；
- 减少 RT FA 投入测试量；
- 保证人员录入数量与过站文件数据一致，防止误操作。

#### 业务规则

1. FT RT 站点允许产出 F；
2. 系统需校验：人工录入的 F 数量 = 过站文件中的 F 数量；
3. 当两者不一致时，系统应阻止过站并给出提示；
4. 少料、压碎等异常芯片数量不得录入 F 数量，应计入 RT 数量。

#### 验证要点

- [ ] FT RT 站点可正常录入并产出 F；
- [ ] F 数量与过站文件一致时允许过站；
- [ ] F 数量与过站文件不一致时禁止过站；
- [ ] 少料、压碎场景下不会误计入 F 数量。

### 3.2 需求二：MES HOLD 缺陷率抓取逻辑调整

#### 现有逻辑

MES HOLD 料检测逻辑中，当前是获取物料在 FA 产出的 F 数量，并基于该数量计算缺陷率，再进行数据分析处理是否 HOLD。

#### 目标逻辑

MES HOLD 料检测逻辑调整为：获取物料在 FT、RT、FA 三站产出的 F 数量，并进行累加求和，再按汇总结果计算缺陷率，最终决定是否 HOLD。

#### 变更目的

- 适配 FT ATE 测试优化后的业务口径；
- 修正仅按 FA 站点统计导致的数据偏差；
- 提升 HOLD 判断准确性。

#### 业务规则

1. 缺陷率计算口径调整为 FT + RT + FA 三站 F 数量汇总；
2. HOLD 判断基于汇总后的缺陷率进行；
3. 原有 HOLD 阈值若无特别说明则保持不变；
4. 统计数据需覆盖三站全部有效过站文件。

#### 验证要点

- [ ] 可正常获取 FT、RT、FA 三站 F 数量；
- [ ] 三站 F 数量汇总正确；
- [ ] HOLD 判断结果符合新的缺陷率统计口径；
- [ ] 新旧逻辑差异可被追溯和比对。

### 3.3 需求三：FT RAW DATE 报表统计逻辑调整

#### 现有逻辑

FA RAW DATE 报表当前通过获取物料在 FA 产出的 F 数量，计算缺陷率并展示报表数据。

#### 目标逻辑

报表调整为抓取 FT、RT、FA 三站中过站文件中的 F 数量，并进行累加求和，再基于汇总结果计算缺陷率，用于报表展示。

#### 变更目的

- 保证报表统计口径与实际业务一致；
- 提升报表缺陷率数据准确性；
- 与 HOLD 缺陷率计算逻辑保持一致。

#### 业务规则

1. 报表统计范围为 FT、RT、FA 三站过站文件中的 F 数量；
2. 缺陷率按三站 F 数量汇总后统一计算；
3. 报表统计结果需与 HOLD 缺陷率计算口径一致；
4. 如有历史展示逻辑依赖原统计方式，需评估兼容性。

#### 验证要点

- [ ] 报表可正确抓取 FT、RT、FA 三站 F 数量；
- [ ] 汇总结果与明细文件一致；
- [ ] 报表缺陷率计算正确；
- [ ] 报表数据与 HOLD 缺陷率统计结果口径一致。

## 四、实现建议

### 4.1 实施顺序

建议按以下顺序实施：

1. 先调整 FT RT FA 过站逻辑；
2. 再调整 HOLD 缺陷率抓取逻辑；
3. 最后调整 FT RAW DATE 报表统计逻辑。

原因如下：

- 过站逻辑是最底层的数据来源变更；
- HOLD 逻辑依赖站点 F 数据统计口径；
- 报表逻辑依赖最终统计结果，适合最后统一调整。

### 4.2 实施范围

- **阶段**：Full Release
- **站点**：CP/FT
- **涉及模块**：
  - FT RT FA 过站逻辑
  - HOLD 缺陷率统计逻辑
  - FT RAW DATE 报表逻辑

## 五、风险与注意事项

### 5.1 已识别风险

| 风险项 | 评估人 | 风险说明 |
|------|------|------|
| 良率损失 | 产品工程 | 当前评估为无明显风险 |
| Setting 不兼容 | AE | 当前未识别明确风险 |
| RE 失效 | RE | 当前未识别明确风险 |
| 产品外观差异 | 产品工程 | 当前未识别明确风险 |
| 材料环保风险 | QS | 当前未识别明确风险 |
| 库存处置 | 产品工程/销管 | 当前未识别明确风险 |
| 客户端应用风险 | CQE/售后 | 当前未识别明确风险 |
| 影响后续制程 | 产品工程 | 需确认是否影响后续统计或业务流程 |
| FSI 工艺变更通知 | 产品工程 | 需确认是否需要同步通知及新建 flow |
| UPH 影响 | 产品工程 | 需上线后重点观察 |

### 5.2 重点关注事项

1. 允许 FT RT 产出 F 后，必须确保数量校验足够严格，避免人员误录；
2. 三站汇总统计会直接影响 HOLD 与报表结果，必须保证数据口径统一；
3. 若三站数据分散在不同表或不同文件来源，需重点关注性能与一致性；
4. 上线前应准备回滚方案，避免影响产线正常过站。

## 六、测试与验收建议

### 6.1 功能测试

- [ ] FT RT 站点允许产出 F；
- [ ] F 数量一致性校验生效；
- [ ] HOLD 缺陷率按三站汇总计算；
- [ ] FT RAW DATE 报表按三站汇总统计；
- [ ] 异常场景提示清晰可用。

### 6.2 数据验证

- [ ] 抽样核对过站文件与系统记录是否一致；
- [ ] 核对 HOLD 计算结果与人工汇总结果是否一致；
- [ ] 核对报表统计结果与源数据是否一致；
- [ ] 比较新旧逻辑差异，确认变更符合预期。

### 6.3 上线检查

- [ ] 相关配置、SQL、报表逻辑已同步更新；
- [ ] 已完成测试环境验证；
- [ ] 已确认上线回滚方案；
- [ ] 已通知相关业务、产品、测试人员；
- [ ] 上线后安排观察期，重点监控 UPH 与缺陷率变化。

## 七、待确认事项

1. F 数量卡控是否允许容差，还是必须完全一致；
2. 少料、压碎等异常数量的录入方式是否已有明确业务口径；
3. HOLD 缺陷率计算的总分母口径是否保持现有规则不变；
4. FT RAW DATE 报表是否需要展示 FT、RT、FA 分站明细；
5. 是否需要对历史数据进行追溯修正。

## 八、结论

本次需求的核心是统一 FT、RT、FA 三站在 F 数量统计上的业务口径，并使过站控制、HOLD 判断和报表展示保持一致。

从实施角度看，建议先解决过站逻辑，再统一统计逻辑，最后调整报表展示，以确保数据来源、业务规则和结果展示形成完整闭环。

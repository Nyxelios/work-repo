## 一、 出站标签数据来源解析与合批/出站双重卡控开发

### 1. 标签 `lotBinString` 数据来源与合批数量计算

#### ① 数据来源
* **打印入口**：调用 `/lotLabelPrint.do?qry=labelPrint&printFlag=lotMergePrint`，使用模板 `批次.btw`。
* **后台核心接口**：`LotLabelPrintAction.java` 中调用：
  ```java
  String lotBinString = lotService.getLotDieBin(lot.getLotRrn());
  ```
* **底层数据库**：从 **`WIP_LOT_DIE_BIN`** 表根据 `LOT_RRN` 查出该批次名下的所有有效 Bin 记录，格式化为 `BIN1:数量 BIN2:数量` 形式的拼接字符串。

#### ② 合批时的数量计算逻辑
在 COM 合批方法（`LotServiceImpl.java:specialMerge` 与 `comWoMerge`）中，系统遍历所有参与合批的子批次：
* **相同 `BIN_ID`**：执行 `Sum(Qty)` 累加，即 `目标批次Bin数量 = 现有数量 + 子批次该Bin数量`。
* **不同 `BIN_ID`**：若目标批次原本没有该 Bin，直接将该 Bin 记录的 `LOT_RRN` 改写归属到新批次。

### 2. `WIP_LOT_DIE_BIN` (实时表) 与 `WIP_LOT_DIE_BIN_HIS` (历史表) 差异分析

在排查合批账实不符时，针对**“为什么历史表有记录，但实时表没有”**的问题，其生命周期与清理机制如下：

| 表名 | 定位 | 数据生命周期 |
| :--- | :--- | :--- |
| **`WIP_LOT_DIE_BIN`** | 实时在制表 | 仅保留当前处于**活动流转中（WIP）**批次的最新有效 Bin 数量。 |
| **`WIP_LOT_DIE_BIN_HIS`** | 历史流水表 | **只增不删**。任何增删改均生成快照流水。 |

#### 导致实时表数据消失的四大业务场景：
1. **合批（Merge）**：子批次的 Bin 记录被 `UPDATE` 归属到新合并的大批次 `LOT_RRN` 下，使用子批次原 `LOT_RRN` 查询实时表为空，但历史表有留存；部分合批逻辑中还会物理删除旧记录。
2. **完工入库（In-storage）**：批次状态变为 `STORAGED` 后脱离车间在制品，系统执行 `deleteLotDieBinByLotRrn` 清理实时表。
3. **数量扣减/修改为 0（Qty = 0）**：工步检验、降级或调整时，若某 Bin 数量变为 0，系统会自动从 `WIP_LOT_DIE_BIN` 中物理删除。
4. **分批（Split）或报废（Scrap）**：子批次若拆走全部数量，母批次对应的 Bin 会被移除；整批报废时实时数据清除。

### 3. 【功能交付】COM 合批源头 Bin 数量一致性强卡控

#### ① 业务痛点
如果参与合批的子批次存在 Bin 数据缺失或未同步，合批后打出的 `批次.btw` 标签上的 Bin 汇总数量会小于批次实际投产数量，导致账实不符。

#### ② 解决方案与实现
在 `LotServiceImpl.java` 中增加 COM 产线专用私有校验方法 `checkComMergeBinQty(Lot lot)`，并在核心合批入口注入强校验：
* **生效入口**：
  - `specialMerge`（CMEG / CATE 工步合盘合批）
  - `comWoMerge`（CRW / CMEG2 工步 AOI 合批）
* **核心校验逻辑**：
  ```java
  /**
   * COM合批后Bin数量与批次数量卡控校验
   */
  private void checkComMergeBinQty(Lot lot) throws MyCimException {
      if (lot == null || lot.getLotRrn() <= 0) {
          return;
      }
      String productClassify = lot.getProductClassify();
      if (StringUtils.isEmpty(productClassify)) {
          LotExt lotExt = getLotExtByLotRrn(lot.getLotRrn());
          if (lotExt != null) {
              productClassify = lotExt.getProductClassify();
          }
      }
      if (StringUtils.isEmpty(productClassify) && StringUtils.isNotEmpty(lot.getOuterOrderNO())) {
          WorkOrder workOrder = prpSetupService.getWorkOrderById(lot.getOuterOrderNO());
          if (workOrder != null) {
              productClassify = workOrder.getProductClassify();
          }
      }
      if (StringUtils.equals(productClassify, WorkOrder.COM)) {
          List<LotDieBin> binList = getLotDieBinList(lot.getLotRrn());
          long totalBinQty = 0L;
          if (CollectionUtils.isNotEmpty(binList)) {
              for (LotDieBin bin : binList) {
                  if (bin.getQty() != null) {
                      totalBinQty += bin.getQty();
                  }
              }
          }
          long lotQty = lot.getQty1() == null ? 0L : lot.getQty1().longValue();
          if (totalBinQty != lotQty) {
              throw new MyCimParameterException(String.format(
                  "合批失败：批次(%s) 的 Bin 总数量(%d) 与批次数量(%d) 不一致，请检查各子批次等级/Bin数据！",
                  lot.getLotId(), totalBinQty, lotQty
              ));
          }
      }
  }
  ```
* **效果**：数量不一致时直接抛出业务异常阻断操作，事务回滚，阻止生成脏批次并彻底拦截打标请求。

## 二、 工艺流程 Route 与 Process 区别及删除指南

> 📄 **详见专项 SOP 文档**：[`10-业务与功能SOP/16-工艺规则与系统配置/工艺流程Route与Process区别及删除指南.md`](../10-业务与功能SOP/16-工艺规则与系统配置/工艺流程Route与Process区别及删除指南.md)

### 核心结论速记：
1. **Process 与 Route 的本质区别**：
   - 二者在底层的对象类型均为 `OBJECT = 'WFL'`、`OBJECT_TYPE = 'ROUTE'`。
   - **Process（主流程）**：`OBJECT_SUBTYPE = 'PROCESS'`，产品定义与工单排产必须使用主流程。
   - **Route（子流程/工艺路线）**：`OBJECT_SUBTYPE = 'PROCEDURE'`，用于在主流程中被嵌套调用。
2. **前台【Delete】按钮置灰原因**：
   - 源码 `PrpSetupAction.java:checkObjectDeleteEnable` 规定：只要 Route 存在至少 1 个版本（`versionObjects.size() != 0`），删除按钮强制置灰禁用（防止孤立版本产生）。
3. **前台正常删除步骤**：
   - 导航进入 Route 维护页 $\to$ 点击底部 **【View Detail】（版本列表）** $\to$ 选中版本执行 **【Delete】（先删除全部版本，若状态为 FROZEN 需先 Unfreeze）** $\to$ 返回 Route 主界面，此时【Delete】按钮激活 $\to$ 点击删除 Route 主对象。
4. **后台级联删除 SQL**（应急备用）：
   ```sql
   -- 1. 查找 INSTANCE_RRN
   SELECT INSTANCE_RRN FROM NAMED_OBJECT 
   WHERE INSTANCE_ID = '你的RouteID' AND OBJECT = 'WFL' AND OBJECT_TYPE = 'ROUTE' AND OBJECT_SUBTYPE = 'PROCEDURE';
   
   -- 2. 依次级联清理
   DELETE FROM WORKFLOW_STEP WHERE WORKFLOW_RRN = :rrn;
   DELETE FROM WORKFLOW_LINK WHERE WORKFLOW_RRN = :rrn;
   DELETE FROM WORKFLOW_PARAM WHERE WORKFLOW_RRN = :rrn;
   DELETE FROM ROUTE_INFO_EXT WHERE ROUTE_RRN = :rrn;
   DELETE FROM NAMED_OBJECT_EXT WHERE INSTANCE_RRN = :rrn;
   DELETE FROM OBJECT_VERSION WHERE INSTANCE_RRN = :rrn;
   DELETE FROM NAMED_OBJECT WHERE INSTANCE_RRN = :rrn;
   COMMIT;
   ```

## 三、 COM 包装表数据查询与销售料号存储机制

### 1. 存储结论
* **确定会存储**。COM 产线包装数据与其他产线统一存储在包装主表 **`MM_PACKED_LOT`**（以 `PRODUCT_CATEGORY = 'COM'` 区分），该表具备专门的 `SALE_MATERIAL_NAME` 字段。

### 2. 表与字段明细
* **表名**：`MM_PACKED_LOT`（在制包装主表） / `MM_PACKED_CHECK_H`（包装历史表）
* **字段名**：`SALE_MATERIAL_NAME`（`VARCHAR2(32)`，实体属性：`PackedLot.saleMaterialName`）。
* **写入时机**：
  1. 办理入库推送到 SAP/WMS 时，调用 `PrpSetupServiceImpl.generateSapPackedLotWoInfo` 从工单表 `WORKORDER.SALE_MATERIAL_NAME` 同步写入；
  2. OIS COM 打包（TBOX / VBOX）时直接赋值并持久化；
  3. 成品包装导入（`FinishedPackageImportAction`）时自动关联工单填入。

### 3. 常见料号/型号字段辨析（防混淆）
* `SALE_MATERIAL_NAME`：销售料号（如客户销售编号）。
* `PRINT_MODEL_ID`：打印型号（标签模板上打印的型号）。
* `PRODUCT_ID`：系统内部产品型号代码（如 `GCxxxx-xx`）。
* `ERP_PRODUCT_ID`：ERP 产品物料编码。
* `SALES_NOTE`：销售备注说明文本（非料号）。

## 四、 本地浏览器（Edge / Chrome）标签打印转 PDF 方案

### 1. 痛点根因
* 现有条码打印脚本 `barcode.js` 采用 `new ActiveXObject("BarTenderActiveX.PrintTest")`。
* ActiveX 属于 IE 专属技术，现代浏览器（Edge / Chrome）出于安全原因已完全禁用，调用直接抛出异常；且没有物理条码机时无法查看标签效果。

### 2. 三大解决方案与适用场景

#### 方案一：后端生成 PDF 流 + 浏览器原生预览与打印（长期正统方案 ⭐⭐⭐）
* **原理**：服务端利用现有模板引擎生成 PDF，前端通过隐藏 iframe 或 PDF.js 打开，触发 `window.print()`。
* **优势**：完美跨浏览器（Edge/Chrome/Firefox 全支持），操作员可预览并自主选择物理打印机或“另存为 PDF”。

#### 方案二：轻量本地代理服务（保持 BarTender 驱动逻辑不变 ⭐⭐）
* **原理**：客户端本地运行轻量中间件（Python/Go/Electron），监听 `localhost:端口`。网页发送 JSON 数据，本地中间件调用本地 BarTender 或虚拟打印机生成 PDF。
* **优势**：前端改动小，保留原有模板格式。

#### 方案三：Edge IE 兼容模式 + 虚拟打印机（零代码修改调试方案 ⭐⭐⭐）
* **适用场景**：个人本地快速排查标签排版、不想动任何系统代码。
* **操作步骤**：
  1. 打开 Edge 浏览器设置 $\to$【默认浏览器】$\to$ 允许在 Internet Explorer 模式下重新加载网站，并将当前 MES 地址添加至列表。
  2. 在 Windows【设置】$\to$【蓝牙和其他设备】$\to$【打印机和扫描仪】中，将 **Microsoft Print to PDF** 设置为系统默认打印机。
  3. 在 Edge IE 模式下触发打印，系统将自动调用虚拟打印机并弹出“文件保存”窗口，直接导出 PDF 预览。

### 2. 车载/量产测试程序（MP / PVT）获取 SQL

系统通过两张配置表维护测试程序：
* **`CAE_PVT_PROGRAM_CONFIG`**：PVT 试验/指定批次程序配置（粒度到批次 `LOT_ID` 或工单 `WORK_ORDER_ID`）。
* **`CAE_MP_PROGRAM_CONFIG`**：MP 量产程序配置（粒度到产品型号 `PRODUCT_ID` 与产品类别 `PRODUCT_CATEGORY`）。

#### 级联查询 SQL（PVT 优先，兜底回退至 MP 量产程序）：
```sql
SELECT
    w.WORKORDER_ID,
    :lotId                                                        AS LOT_ID,
    w.PRODUCT_ID,
    -- CATE1 测试程序（优先 PVT，次选 MP）
    COALESCE(pvt.CATE1_RELEASE_EXE, mp.CATE1_RELEASE_EXE)         AS CATE1_RELEASE_EXE,
    -- CATE2 测试程序
    COALESCE(pvt.CATE2_RELEASE_EXE, mp.CATE2_RELEASE_EXE)         AS CATE2_RELEASE_EXE,
    -- CATE1 测试二级代码
    COALESCE(pvt.CATE1_TEST_BIT, mp.CATE1_TEST_BIT)               AS CATE1_TEST_BIT,
    -- CATE2 测试二级代码
    COALESCE(pvt.CATE2_TEST_BIT, mp.CATE2_TEST_BIT)               AS CATE2_TEST_BIT,
    NVL(pvt.PROGRAM_CATEGORY, 'AUTO')                             AS PROGRAM_CATEGORY,
    pvt.TEST_TIME
FROM WORKORDER w
-- 1. 关联 PVT 配置（按 Lot 或 WorkOrder 匹配）
LEFT JOIN CAE_PVT_PROGRAM_CONFIG pvt
  ON (pvt.LOT_ID = :lotId OR (pvt.LOT_ID IS NULL AND pvt.WORK_ORDER_ID = w.WORKORDER_ID))
-- 2. 关联 MP 量产配置（按产品主型号匹配）
LEFT JOIN CAE_MP_PROGRAM_CONFIG mp
  ON mp.PRODUCT_ID = SUBSTR(w.PRODUCT_ID, 1, INSTR(w.PRODUCT_ID || '-', '-') - 1)
 AND mp.PRODUCT_CATEGORY = w.PRODUCT_CATEGORY
WHERE w.WORKORDER_ID = :workOrderId;
```

## 六、 Java 集合 Bin 过滤匹配逻辑优化（精确匹配 sourceBin 与 sourceBin*）

### 1. 原始代码隐患分析
```java
// 原始逻辑存在全子串包含漏洞
if (bin.getBinId().contains(sourceBin)) {
    goodQty = goodQty.add(new BigDecimal(bin.getUnpackedQty()));
}
```
* **问题**：`String.contains()` 判定的是子串包含（`indexOf >= 0`）。当 `sourceBin = "MA"` 时，不仅 `MA`、`MA*` 会被命中，`MA1`、`MA2`、甚至 `XMA`、`DAMAGE` 也会返回 `true`，导致非目标 Bin 的数量被错误累加进 `goodQty`。

### 2. 优化改造规范
若业务要求：**严格只匹配 `sourceBin` 本身以及其对应的尾批/特殊批 `sourceBin*`**（例如 `MA` 与 `MA*`，坚决排除 `MA1`、`XMA` 等）：

#### 推荐写法（使用 `StringUtils.equals` 防空指针）：
```java
String binId = bin.getBinId();
if (StringUtils.equals(binId, sourceBin) || StringUtils.equals(binId, sourceBin + "*")) {
    goodQty = goodQty.add(new BigDecimal(bin.getUnpackedQty()));
}
```

#### 防错容灾写法（防止 `sourceBin` 参数本身已带 `*` 导致拼接出 `**`）：
```java
String baseBin = sourceBin.endsWith("*") ? sourceBin.substring(0, sourceBin.length() - 1) : sourceBin;
String binId = bin.getBinId();
if (StringUtils.equals(binId, baseBin) || StringUtils.equals(binId, baseBin + "*")) {
    goodQty = goodQty.add(new BigDecimal(bin.getUnpackedQty()));
}
```

#### 匹配效果对比矩阵：

## 一、 核心工作项：LOT测试程序配置增加抓取量产Recipe功能

### 1. 业务背景与问题
在半导体封装测试业务中，针对研发工程批次或试产批次，操作员在【LOT测试程序配置】（`/mycim2/lotTestPragramConfig.do`）模块为工单建立测试程序时：
- 以前需要在【BOM程序Recipe配置】（`GC_RECIPE_PROGRAM_CONFIG`）先手工核对量产（MP）主从程序名，再手工逐一为该工单新建 PVT 配置；
- 手工录入繁琐、容易产生疏漏，且不同界面频繁切换降低产线工程准备效率。

**本次优化目标**：在 LOT 测试程序配置界面新增勾选复选框【抓取量产Recipe】，实现工单级试产程序（PVT）与量产基准程序（MP）的一键联动与自动落库。

---

### 2. 详细实现方案

#### ① 界面交互设计 (`lotTestPragramConfigForm.js`)
- 在表单第 2 行右侧新增复选框组件：
  - `id`: `'syncRecipeProgram'`
  - `fieldLabel`: `'抓取量产Recipe'`
- 在 `Ext.doAdd` 中抓取该复选框值：
  ```javascript
  var syncRecipeProgram = false;
  var syncRecipeComp = Ext.getCmp('syncRecipeProgram');
  if (syncRecipeComp) {
      syncRecipeProgram = syncRecipeComp.getValue();
  }
  ```
- 通过 Ajax 参数 `syncRecipeProgram: syncRecipeProgram` 传至后台。

#### ② 数据实体层 (`LotTestPragramConfig.java`)
- 增加非持久化字段：
  ```java
  @javax.persistence.Transient
  private Boolean syncRecipeProgram;
  ```

#### ③ 控制器层 (`LotTestPragramConfigAction.java`)
- 解析 `syncRecipeProgram` 参数（支持从 Bean 自动注入及 Request 兜底解析）；
- 提取 Session 当前操作人工号，显式注入 `ThreadLocalContext.setUsername(username)`；
- 转发至重载服务方法：
  ```java
  boolean syncRecipe = (config.getSyncRecipeProgram() != null && config.getSyncRecipeProgram())
          || Boolean.parseBoolean(request.getParameter("syncRecipeProgram"));
  LotTestPragramConfig data = prpSetupService.createLotTestPragramConfig(config, username, syncRecipe);
  ```

#### ④ 业务服务层 (`PrpSetupServiceImpl.java`)
- **前置判定**：当 `syncRecipeProgram == true` 时执行同步流程；若为 `false`，则 100% 保持既有逻辑不变；
- **BOM 型号提取**：获取工单对应产品型号 `workOrder.getProductId()`，如果包含 `-`，通过 `lastIndexOf("-")` 截取**最后一个 `-` 之前的内容**（去掉最后一个 `-` 及其后尾缀，保留主型号，如 `GC5035-MCKD0-4.7` 提取为 `GC5035-MCKD0`）作为 `BOM_ID`；若不含 `-`，则使用原值；
- **BOM 版本获取**：提取工单绑定的 `workOrder.getBomVersion()`；
- **量产程序检索**：
  ```sql
  SELECT * FROM GC_RECIPE_PROGRAM_CONFIG
  WHERE CONFIG_TYPE = 'MP' AND BOM_ID = :bomId AND BOM_VERSION = :bomVersion
  ```
  若检索结果为空，直接抛出 `MyCimException("未找到型号[" + bomId + "]版本[" + bomVersion + "]对应的量产程序配置")` 阻止保存；
- **PVT 状态判定与处理**：
  - 查询当前工单在 `GC_RECIPE_PROGRAM_CONFIG` 中现有的 `PVT` 记录（`WORK_ORDER_ID = :workOrderId AND CONFIG_TYPE = 'PVT'`）；
  - 遍历匹配各量产工步：
    - **若已存在该工步的 PVT 记录**：更新其主程序 `recipeProgram`、串联程序 `recipeProgramInline`、修改人与修改时间，保存并写入 `GC_RECIPE_PROGRAM_CONFIG_H` 历史表（事务类型 `MODIFY`）；
    - **若不存在该工步的 PVT 记录**：新建一条 PVT 记录，工单号设为当前工单、工步号同步量产工步（`OPERATION_ID`）、`CONFIG_TYPE = 'PVT'`、写入主程序与从程序、创建人与修改人，保存并写入 `GC_RECIPE_PROGRAM_CONFIG_H` 历史表（事务类型 `CREATE`）；
- **健壮性保障**：优化了 `recordRecipeProgramConfigHistory` 方法，当 `ThreadLocalContext.getUsername()` 为空时自动回退为实体的 `updatedBy`/`createdBy`，杜绝空指针异常。

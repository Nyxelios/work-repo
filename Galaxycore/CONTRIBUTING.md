# Galaxycore MES 文档维护规范


## 二、文档命名规范

### 2.1 命名格式

```text
[模块]-[功能简述].md
```

示例：
- `WorkOrder-工单投入.md`
- `LOT-CDES风逃气孔减数功能.md`
- `BUG-InnerOrderNO被覆盖问题.md`

### 2.2 禁止事项

- 不使用含义不清的文件名
- 不使用过长文件名，建议不超过 40 个字符
- 不在文件名中使用非法字符：`/ \ : * ? " < > |`
- 不混用全角和半角符号造成检索困难

## 三、文档元数据

每篇正式文档建议在开头包含 frontmatter：

```yaml
---
title: 文档标题
date: YYYY-MM-DD
author: 作者名
status: draft | review | completed
tags: [标签1, 标签2]
---
```

### 3.1 状态定义

| 状态 | 含义 | 使用场景 |
|------|------|----------|
| `draft` | 草稿 | 正在编写，内容未完成 |
| `review` | 待审核 | 内容已成型，待复核 |
| `completed` | 已完成 | 可作为正式资料使用 |

### 3.2 标签建议

| 标签 | 用途 |
|------|------|
| `#工单` | 工单管理相关 |
| `#晶圆` | 晶圆 / Wafer 相关 |
| `#工艺` | 工艺规划与配置 |
| `#包装` | 包装、FQC、PKG 相关 |
| `#COM` `#FT` `#CP` `#RW` | 产线类型 |
| `#BUG` | 缺陷与异常分析 |
| `#运维` | 环境、部署、数据处理 |
| `#开发` | 开发知识与实现记录 |
| `#培训` | 业务培训与 SOP |
| `#工作流` | 需求推进与任务跟踪 |
| `#架构` | 系统结构与模块关系 |

## 五、编写原则

### 5.1 内容要求

1. 先说明业务背景，再写实现或操作细节
2. 面向读者明确：是给业务、开发、运维还是新人看
3. 同一术语保持一致，尽量使用 MES 标准说法
4. 流程类内容优先写清输入、处理、输出和例外情况
5. 涉及代码、SQL、配置时，尽量附上适用范围

### 5.2 质量检查

- [ ] 标题层级清晰
- [ ] 文档目标明确
- [ ] 有必要的业务背景
- [ ] 有关键步骤或结构说明
- [ ] 有注意事项或边界条件
- [ ] 相关文档之间可互相导航

## 六、工作流文档管理

### 6.1 目录约定

```text
2.工作流/
├── YYYY QN/
│   ├── Done/
│   │   └── BUG/
│   ├── TODO/
│   │   ├── AI协作记录/
│   │   └── TBC/
│   ├── 新需求/
│   ├── 系统改进/
│   └── 或取消/
├── 历史需求/
├── 工作日志/
└── 专项评估与验证/
```

### 6.2 生命周期

- `TODO`：待处理事项
- `Done`：已完成事项
- `TBC`：待确认事项
- `或取消`：取消或暂停事项

同名事项不建议同时保留在 `TODO` 和 `Done`，完成后应移动而不是复制。

## 七、维护节奏建议

### 每周
- 检查 `TODO` 中是否有过期内容
- 将已完成事项归档到 `Done`

### 每月
- 检查导航文档与目录是否一致
- 清理重复文档与失效链接

### 每季度
- 整理当季工作流资料
- 提炼可沉淀内容到 `1.MES系统/`
- 清理明显无效或重复的过程文档

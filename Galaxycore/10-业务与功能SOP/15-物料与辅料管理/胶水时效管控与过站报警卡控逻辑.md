# 胶水时效管控与过站报警卡控逻辑

## 1. 业务背景与概述

在半导体与芯片封装生产线（如 `CDPS`、`CDES`、`CBA`、`CGN_AE` 等用胶工步）中，胶水（GLUE）的常温暴露时效、保质期和回温状态对产品封装质量起着决定性作用。

MES 系统对胶水在生命周期中的各阶段（回温、脱泡、上料绑定、出站/进站过站）建立了全流程管控机制。本文档详细记录胶水时效的判定规则、出入站报警及卡控机制。

---

## 2. 胶水时效计算与判定公式

在批次过站时，系统会根据机台上当前 Mount 绑定的胶水实时计算**剩余可用时效**。

### 2.1 核心计算公式

$$
\text{剩余可用时间(小时)} = \frac{\text{总控制时间} - \text{本次回温使用时间} - \text{历史累计使用时间}}{1000 \times 60 \times 60}
$$

### 2.2 参数字段及来源

| 关键参数 | 字段名 / 来源 | 业务含义与说明 |
| :--- | :--- | :--- |
| **总控制时间** | `TOTAL_CONTROL_TIME`（来自胶水类型定义 `TOOL_GLUE_TYPE`） | 胶水在常温开封状态下允许暴露的最大总时效（单位：小时，例如 24H 或 48H）。 |
| **本次回温使用时间** | `System.currentTimeMillis() - glue.getTemperatureStartTime().getTime()` | 胶水自最近一次在 MES 执行 Active（回温激活）打上时间戳后，到当前系统时间所过去的毫秒数。 |
| **历史累计使用时间** | `TOTAL_USAGE_TIME`（来自 `TOOL_GLUE`） | 若胶水曾做过中途冷冻（`GlueFrozen`），系统在冻结时累加记录的历史暴露总时长。若一次性使用未中途冻结，该值为 0。 |
| **出厂有效日期** | `EFFECTIVE_DATE`（来自 `TOOL_GLUE`） | 胶水外包装标签标明的物理过期绝对日期（YYYY-MM-DD）。 |

## 3. 过站报警与卡控行为对照

系统在不同的操作环节对胶水时效采取了不同强度的管控策略：

| 环节 | 涉及工步 / 页面 | 触发条件 | 界面提示与系统表现 | 卡控性质 |
| :--- | :--- | :--- | :--- | :--- |
| **出站（Move Out）提前预警** | `CDPS`、`CDES`、`CBA`、`CGN_AE`<br>`moveout.jsp` | $0 < \text{剩余可用时间} < 2\text{小时}$ | 浏览器弹窗提示：<br>`"胶水即将过期，请及时更换！"` | **软提示（不阻断）**<br>点击确定后继续执行出站提交。留给产线 2 小时提前备胶缓冲期。 |
| **出站（Move Out）超时报警** | 同上<br>`moveout.jsp` | $\text{剩余可用时间} < 0$ | 浏览器弹窗提示：<br>`"胶水已过期！"` | **软提示（不阻断，过一次报警一次）**<br>后端不抛异常，前端每次点出站弹窗报警，操作员点击【确定】后仍能正常完成出站。 |
| **进站（Move In）强制拦截** | 开启 `checkMaterialFlag = on` 的工步<br>`movein.jsp` | 1. $\text{当前日期} > \text{有效日期}$<br>2. 暴露时间超过总控制时间 | 弹窗报错：<br>`I_glue_has_expried`<br>或 `I_total_used_time_exceed_total_control_time` | **硬卡控（强制阻断，过不了站）**<br>后台直接抛出 `MyCimException`，前端中断交易提交，批次无法进站。 |
| **机台上料（Glue Mount）** | 机台上料绑定页面<br>`glueMount.jsp` | 1. 胶水已过期<br>2. 累计时间超限<br>3. 回温未结束或未脱泡 | 弹窗报错：<br>`GLUE_HAS_BEEN_EXPRIED` 等 | **硬卡控（强制阻断）**<br>不合规的胶水直接拒绝 Mount 到机台上。 |

## 4. 关键源码位置

### 4.1 出站预警与报警逻辑
- **文件**：`core/src/model/src/com/mycim/webapp/actions/wip/CheckMaterialAction.java`（第 82 ~ 117 行）
- **核心代码片段**：
  ```java
  double limitTemperatureTime = now.getTime() - glue.getTemperatureStartTime().getTime();
  double totalUsageTimeValue = glue.getTotalUsageTime() * 60 * 60 * 1000;
  double totalControlTimeValue = glue.getTotalControlTime() * 60 * 60 * 1000;
  double remainingHours = (totalControlTimeValue - limitTemperatureTime - totalUsageTimeValue) / 1000 / 60 / 60;

  // 1. 提前 2 小时预警
  if (0 < remainingHours && remainingHours < 2) {
      msg = "胶水即将过期，请及时更换！";
  } 
  // 2. 超期过期提示
  else if (remainingHours < 0) {
      msg = " 胶水已过期！";
  }
  writeDefaultResponseJson(msg); // 以正常状态返回，未抛异常
  ```

### 4.2 前端出站响应逻辑
- **文件**：`core/web/wip/moveout.jsp`（第 395 ~ 449 行、第 457 ~ 541 行）
- **核心代码片段**：
  ```javascript
  $.ajax({
  ```

## 5. 产线现状分析与优化建议

### 5.1 现场痛点分析
1. **产线提前换胶触发不了卡控**：
   因为出站会在到期前 **2 小时** 频繁弹窗提醒，员工有充分的缓冲时间去备料换胶，因此大部分胶水在到期前就被替换下线。
2. **过期后依然可以出站（软报警）**：
   出站时即使胶水已超期，前端仅执行了浏览器原生 `alert()`，操作员只要点击【确定】按钮，批次依旧会被提交出站成功。这导致现场形成了“每次过站都报警一次，但依然能过”的习惯，存在品质管控脱节的隐患。

### 5.2 优化改造方案（供业务与架构参考）
- **出站硬阻断改造**：
  若品质要求胶水过期后绝对禁止出站，可在 `CheckMaterialAction.java` 中将 `remainingHours < 0` 的情况改为抛出明确异常（如 `throw new MyCimParameterException("胶水已过期，禁止出站，请先更换胶水！");`），将出站环节的“软提示”提升为与进站一致的“硬卡控”。
- **预警阈值可配置化**：
  目前代码中提前 2 小时是写死的（`< 2`），后续可考虑配置到胶水类型参数或工步参数中，便于不同胶水灵活定义预警时长（如 1 小时或 3 小时）。

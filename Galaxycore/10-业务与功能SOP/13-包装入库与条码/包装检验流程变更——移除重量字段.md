# 包装检验流程变更——移除重量（WEIGHT）字段

## 1. 文档概述

| 项目 | 内容 |
|------|------|
| 文档名称 | 包装检验流程变更——移除重量字段需求规格说明 |
| 项目名称 | mycim2-semi |
| 创建日期 | 2026-05-08 |
| 文档版本 | V1.0 |
| 变更类型 | 功能优化——字段移除 |
| 涉及模块 | 包装检验（PackageCheckout） |

## 2. 变更背景

现包装检验流程中，操作员在执行包装检验通过（PASS）操作时，需要手动输入包装箱重量（weight）。经业务确认，该重量字段在实际生产流程中**无业务使用场景**，仅作为记录存储，不参与任何后续业务逻辑运算（如不参与库存核算、不参与出货重量计算、不参与品质追溯判定等）。

为提高操作效率、减少操作员不必要的输入步骤、降低人为输入错误的可能性，现决定**移除包装检验流程中的重量（WEIGHT）输入字段**。

## 3. 变更范围

### 3.1 变更清单

| 模块 | 文件 | 变更内容 |
|------|------|----------|
| 前端UI | `packageCheckOutAspectSampling/aspectSamplingForm.js` | 移除重量输入框组件、校验逻辑、AJAX传参 |
| 后端Action | `PackageCheckoutAction.java` | 移除weight参数获取和实体赋值 |
| 数据库模型 | `PackedLot.java` | 仅移除业务赋值，保留模型字段定义 |

### 3.2 不变更内容

| 内容 | 原因 |
|------|------|
| 数据库表 `PackedLot.WEIGHT` 列 | 不删除列定义，保留历史数据 |
| `PackedLot.java` 模型字段 `weight` | 保留字段定义，避免破坏ORM映射和已有历史数据读取 |
| 包装检验NG流程 | 该流程原就不涉及weight字段，无需修改 |
| 其他模块的weight字段（如库存模块 `LotInventoryDO.weight`） | 独立业务领域，与本变更无关 |

## 4. 变更前流程

### 4.1 当前操作流程

```
操作员打开包装检验弹窗
    ↓
填写 [抽检数量] 输入框
    ↓
填写 [重量] 输入框                    ← 需要手动输入
    ↓
  校验：重量不能为空
    ↓
  校验：重量必须为正整数
    ↓
填写 [不良数] 表格
    ↓
点击 [PASS] 按钮
    ↓
AJAX发送数据（含weight参数）
    ↓
后端接收 → 设置到PackedLot实体 → 保存到数据库WEIGHT列
    ↓
关闭弹窗，更新状态为PQC1
```

### 4.2 当前涉及代码

**前端 — weight输入框定义**
```js
{
    xtype : "mycim.textfield",
    name : 'weight',
    id : 'weight',
    fieldLabel : i18n_FLD_weight,       // "重量"
    columnWidth: 0.3,
    value : '',
    enableKeyEvents : true,
    targetIds : 'weight'
}
```

**前端 — weight校验逻辑**
```js
var weight = Ext.getCmp('weight').getValue();
if (weight == '') {
    MyCim.notify.alert(i18n_FLD_weight_cant_empty);  // "重量不能为空"
    return;
}
if (!/^[0-9]*$/.test(weight)) {
    MyCim.notify.alert(i18n_msg_Please_fill_in_positive_integers_in_the_weight);  // "请输入正整数"
    return;
}
```

**后端 — weight处理**
```java
// 从请求中获取
String weight = request.getParameter("weight");

// 设置到实体
packedLot.setWeight(Double.valueOf(weight));
```

## 5. 变更后流程

### 5.1 目标操作流程

```
操作员打开包装检验弹窗
    ↓
填写 [抽检数量] 输入框                ← 保持不变
    ↓
填写 [不良数] 表格                     ← 保持不变
    ↓
点击 [PASS] 按钮                      ← 保持不变
    ↓
AJAX发送数据（不再含weight参数）      ← 简化
    ↓
后端处理 → 保存到数据库                ← 不再设置weight值
    ↓
关闭弹窗，更新状态为PQC1
```

### 5.2 变更要点

| 变化点 | 变更前 | 变更后 |
|--------|--------|--------|
| 界面元素 | 显示"重量"输入框 | 不显示重量输入框 |
| 必填校验 | 重量不能为空 + 必须是正整数 | 无校验项 |
| 自动聚焦 | `Ext.getCmp('weight').focus()` | 取消聚焦 |
| AJAX参数 | 发送 `weight: weight` | 不发送weight参数 |
| 后端处理 | `request.getParameter("weight")` → `setWeight()` | 不获取、不设置weight |
| 数据库WEIGHT列 | 写入用户输入值 | 不写入（保持默认值null） |

## 6. 详细代码修改说明

### 6.1 前端文件

**文件路径**: `core/web/wip/packageCheckOutAspectSampling/aspectSamplingForm.js`

#### 6.1.1 移除输入框组件

移除以下组件定义（原第34-42行）：

| 字段 | 值 | 说明 |
|------|-----|------|
| name | weight | 组件名称 |
| id | weight | 组件ID |
| fieldLabel | i18n_FLD_weight | 标签：重量 |
| columnWidth | 0.3 | 列宽 |

#### 6.1.2 移除自动聚焦

移除 `Ext.getCmp('weight').focus(false, 100)` 调用。

#### 6.1.3 移除取值与校验逻辑

移除以下三段代码：
- `var weight = Ext.getCmp('weight').getValue();` — 取值
- `if (weight == '') { ... }` — 空值校验
- `if (!/^[0-9]*$/.test(weight)) { ... }` — 正整数格式校验

#### 6.1.4 移除AJAX参数

在 `params` 对象中移除 `weight: weight` 字段。

### 6.2 后端文件

**文件路径**: `core/src/model/src/com/mycim/webapp/actions/wip/PackageCheckoutAction.java`

#### 6.2.1 移除请求参数获取

在 `packageChexkoutPass()` 方法中，移除：
```java
String weight = request.getParameter("weight");
```

#### 6.2.2 移除实体赋值

在循环中移除：
```java
packedLot.setWeight(Double.valueOf(weight));
```

### 6.3 模型层（不做修改）

**文件路径**: `core/src/valueobject/src/com/mycim/wip/model/PackedLot.java`

| 操作 | 说明 |
|------|------|
| 保留 `private Double weight` 字段 | 避免破坏ORM映射关系 |
| 保留 `@Column(name = "WEIGHT")` 注解 | 与数据库表结构保持一致 |
| 保留 `getWeight()` / `setWeight()` 方法 | 其他历史数据读取场景可能使用 |

## 7. 数据库变更

| 变更项 | 操作 |
|--------|------|
| `PackedLot.WEIGHT` 列 | **不做删除** |
| 已有历史数据 | **保留不变** |
| 新写入行为 | 不再向该列写入数据（保持null） |

## 8. 影响分析

### 8.1 业务影响

| 维度 | 影响评估 |
|------|----------|
| 操作效率 | 提升：操作员每笔PASS操作减少一个必填项，减少约10-15秒操作时间 |
| 数据质量 | 消除因手动输入导致的重量数据错误 |
| 历史数据 | 已有历史数据完整保留，不受影响 |
| 下游系统 | 无影响：重量字段原不参与下游任何业务逻辑 |

### 8.2 系统影响

| 维度 | 影响评估 |
|------|----------|
| 前端 | 界面少一个输入框，布局微调（column布局自适应） |
| 后端 | 移除两行代码，无逻辑变更 |
| 数据库 | 无结构变更 |
| 接口 | 前端到后端的AJAX参数减少一个字段，不影响后端接口兼容性 |
| 报表/查询 | 如有基于WEIGHT字段的报表查询，需单独评估（当前无相关报表） |

## 11. 附录

### 11.1 数据流对比

**变更前** PASS数据流：
```
UI输入(weight) → JS校验 → AJAX(weight参数) → Action解析 → PackedLot.setWeight() → DB.WEIGHT列
```

```
(无weight输入) → JS无校验 → AJAX(无weight参数) → Action不处理 → PackedLot.weight保持null → DB.WEIGHT列不写入
```

# 工单的查询

## 工单投入及一览
### 查询参数以及卡控

前端参数值

| 名称      | 类表值               |
| ------- | ----------------- |
| 生产地     | `$$LOCATION`      |
| 工单类型    | `$$WORKORDERTYPE` |
| wafer属性 | `$WAFERPROPERTY`  |
| 产品分类    | `$$PORT_GATEGORY` |

除前端传入的值外，后端查询卡控

- `STATUS IN ('STARTED','CREATED', 'ISSUE')`
- `PLANNED_QTY <> 0`

### 查询结果

1.分页查询`WORKORDER` 表
2.如果是COM 量产或者实验工单
- 💰 **计算“总接收量”（`RECEIVE_QTY`）：** 直接把物料表（`wmml`）里所有的“接收数量”加在一起。
- 📦 **计算“当前总余量”（`CURRENT_QTY`)** 系统在把每一行数据加起来之前，会先做一个判断（`CASE WHEN`）：
    - **情况 A：** 如果在库存表（`LOT_INVENTORY`）里**能找到**这个批次（`li.LOT_NUMBER IS NOT NULL`），那就按库存来算：**当前余量 = 入库量（`RECEIPT_QTY`）减去 出库量（`ISSUE_QTY`）**。
    - **情况 B：** 如果在库存表里**找不到**这个批次，那就直接拿物料表里的“当前数量（`wmml.CURRENT_QTY`）”来凑数。
    - 最后，把每一行算出来的这个余量全部加总（`SUM`）。
- **计算IRA接收数量**：`AM_RECEIVE` ：STATUS = 'RECEIVED' AND PRODUCT_TYPE = 'IR'
- **计算IRA退料数量**：`AM_RECEIVE` ：STATUS = 'RETURN' AND PRODUCT_TYPE = 'IR'
- **计算IRA剩余数量**：`IRA接收数量 -（RECEIVE_QTY - CURRENT_QTY）* （planqty / RECEIVE_QTY）`
- **待投批数量** (`lotPlan` / `unBatchLotTotalQty`)： 依赖 `lot_plan` 表查询结果，按产品分类 (`productClassify`) 区分逻辑：
    - **WLT**：直接取 `lot_plan` 列表的总行数（`size()`）。
    - **OIS**：关联查询物料批次表（`WmsMmsMaterialLot`），仅累加状态为“已发料”（`STATUS_ISSUE`）的 `lotPlan.qty1`。
    - **SENSOR_CP / LCD_CP 及其他常规品**：直接累加所有的 `lotPlan.qty1`。
- **未建批数量** (`unBuiltLotQty`)： 当工单状态不为 `CLOSED` 时触发计算，按业务类型分支：
    - **测试类及特定工单**（首字母为 `T`，或分类为 `FT`, `FT_AE`, `RW`, `COG`, `LCD_CP`, `SENSOR_CP`, `OIS`, `WLT`）：不参与扣减，强制设为 **0**。
    - **COM 量产/实验单**：计算公式为 **计划数量 (`plannedQty`)** - **历史建批数量 (`planHistoryQty`)**。
    - **常规默认工单**：计算公式为 **计划数量** - **完工数量** - **在制数量** - **报废数量** - **待投批数量 (`unBatchLotTotalQty`)**。
### 批次的建批/投批

#### 建批入口

- **入口位置**：列表中的 **未建批数量** (`unBuiltLotQty`)
- **显示方式**：当 `unBuiltLotQty` 有值时，前端将该数量渲染为可点击链接
- **点击动作**：点击后打开建批页面，并带入当前工单号 `workorderId`

#### 投批明细特殊卡控

- **OIS 工单**：不是直接展示全部 `lot_plan`
  - 会额外关联 `WmsMmsMaterialLot`
  - **仅保留状态为 `STATUS_ISSUE` 的批次**
- **部分工单不允许取消计划**：后端会返回 `isPlanWorkorderFlag`
  - **工单号首字母为 `T`**
  - 或产品分类为 `FT`、`FT_AE`、`RW`、`COG`、`LCD_CP`、`SENSOR_CP`、`WLT`
  - 前端收到该标记后，会将 **取消计划** 按钮置灰
- **注意**：这里的“不可取消计划”范围 **不包含 `OIS`**

#### 投批操作

- **按钮名称**：`计划投批`
- **前置校验**：必须先勾选至少一个 lot
  - 若未勾选，前端提示：`PleaseChooseLot`
- **提交方式**：将勾选的 `lotId` 组装成逗号分隔字符串
- **跳转地址**：`/mycim2/lotplansave.do?create=1&lotId=lot1,lot2,...`
- **业务含义**：对选中的计划批次执行投批

#### 取消投批操作

- **按钮名称**：`取消计划`
- **前置校验**：必须先勾选至少一个 lot
  - 若未勾选，前端提示：`PleaseChooseLot`
- **提交方式**：Ajax 提交勾选的 `lotId` 列表
- **请求地址**：`/mycim2/lotplansave.do?cancelLotPlanList=1&lotIds=lot1,lot2,...`
- **执行成功后**：
  - 关闭“计划投批信息”弹窗
  - 刷新主列表数据

# 工单历史记录功能说明

### 2.1 查询条件

`WorkOrderHistoryForm` 只有一个核心查询条件：

1. 工单号：`wordOrderformId`

前端固定分页大小为 `20`，并自动带以下参数：

1. `start`
2. `limit`
3. `wordOrderformId`

`workOrderHistoryGrid.js` 中定义了页面展示字段。当前页面主要展示以下信息：

1. `workorderId`：工单号
2. `transTime`：事务时间
3. `transType`：事务类型
4. `transDescription`：事务描述
5. `owner`：操作人
6. `productId`：产品型号
7. `planPutTime`：计划投片时间
8. `planTime`：计划完成时间
9. `plannedYield`：计划数量
10. `completeQty`：完工数量
11. `wipQty`：在制数量
12. `scrapQty`：报废数量
13. `workOrderType`：工单类型
14. `productClassify`：产品分类
15. `status`：工单状态
16. `createUser`：创建人
17. `transRrn`：事务 RRN
18. `comments`：备注

从展示结果看，这个页面不是只看“操作日志”，而是看某次事务时点下的工单快照。也就是说，一条历史记录同时包含：

1. 事务元信息：如 `transType`、`transTime`、`owner`
2. 工单业务快照：如 `plannedYield`、`wipQty`、`scrapQty`、`status`

### 4.3 查询SQL

1. 查询表：`WORKORDER_H`
2. 查询条件：`WORKORDER_ID = ?`
3. 排序规则：`TRANS_RRN desc, SCRAP_QTY desc`
4. 返回方式：分页

事务描述：`$$TRANS_TYPE_WO`
1. `CREATE`
2. `STARTE`
3. `MODIFY`
4. `DELETE`
5. `CLOSE`
6. `AUTOCLOSE`

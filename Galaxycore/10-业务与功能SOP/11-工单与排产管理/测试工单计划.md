# 测试工单计划

## 一、功能定位

测试工单计划用于在工单计划阶段筛选可用物料、辅助测试工单排产，并支持按入库备注等字段做条件查询。

该功能的核心价值在于：
- 为测试工单提供物料筛选入口
- 支撑计划人员快速定位可用批次
- 在查询阶段提前过滤不满足条件的数据

## 二、入库备注模糊搜索需求

### 2.1 需求说明

在测试工单计划页面中，增加“入库备注”模糊搜索：
- 如果用户输入入库备注，则按模糊匹配查询
- 如果用户不输入入库备注，则只查询入库备注为空的数据

相关基础表：

```sql
SELECT * FROM WMS_MMS_MATERIAL_LOT;
```

## 三、前后端实现思路

### 3.1 Action 层接收参数

在 `WorkOrderPlanAction.java` 中构建查询参数对象时，增加 `shipNote` 参数读取，并写入 `WorkOrderPlanPara`。

核心思路：
- 页面传入 `shipNote`
- Action 层读取参数
- 参数对象统一向下传递到 Repository 查询层

### 3.2 参数对象扩展

在 `WorkOrderPlanPara` 中新增字段：
- `treasuryNote`

用途：
- 统一承载入库备注查询条件
- 作为 Repository 查询时的筛选参数

## 四、Repository 查询改造

### 4.1 改造原则

涉及测试工单计划查询的方法，需要统一增加 `RESERVED4` 的条件判断：
- 有值：`bothLike`
- 空值：`isNull`

### 4.2 典型查询逻辑

```java
if (StringUtils.isNotEmpty(workorderPlanPara.getTreasuryNote())) {
    sqlBuilder.and("RESERVED4").bothLike(workorderPlanPara.getTreasuryNote());
} else {
    sqlBuilder.and("RESERVED4").isNull();
}
```

### 4.3 需要同步修改的方法类型

本次问题的关键不是只改一个查询方法，而是要把所有入口都改完整。常见包括：
- 返回 `List` 的查询方法
- 返回 `ResultPage` 的分页查询方法

如果只改其中一种，会出现：
- 页面显示结果和统计数量不一致
- 页面显示 0 条，但总数不为 0

## 五、前端页面改造

在 `workOrderPlanForm.js` 中新增查询字段：
- `shipNote`
- 标签名称：`入库备注`

前端注意点：
- 前后端字段名必须一致
- 页面传参名称和 Action 读取名称必须对齐

## 六、问题复盘

### 6.1 字段命名不一致

本次开发中，一个典型问题是：
- 前端写成了 `treasuryNote`
- 实际后端接收使用的是 `shipNote`

结果会导致：
- 页面看似传值了
- 后端实际拿不到参数
- 查询条件不生效

### 6.2 多入口查询遗漏

测试工单计划查询并不是只走一个方法，而是存在多种查询入口。只改一部分方法，会造成：
- 查询列表结果与统计结果不一致
- 分页数量异常
- 用户误以为查询条件无效

## 七、排查建议

### 7.1 前端排查
- 确认字段名是否一致
- 确认页面参数是否实际提交
- 确认查询按钮触发了哪些接口

### 7.2 后端排查
- 确认 `Action` 是否拿到参数
- 确认参数对象是否已赋值
- 确认所有 Repository 方法都已补充过滤逻辑

### 7.3 数据排查
- 检查 `WMS_MMS_MATERIAL_LOT.RESERVED4` 的实际值
- 区分空字符串与 `NULL`
- 核对模糊匹配与空值匹配的结果差异

## 八、结论

这个需求表面上只是“加一个模糊搜索字段”，但实际涉及：
- 页面字段传参
- Action 参数接收
- 参数对象扩展
- Repository 多方法统一改造
- 分页与列表查询一致性

因此，这类查询增强需求要重点关注“是否所有查询分支都改到了”。
